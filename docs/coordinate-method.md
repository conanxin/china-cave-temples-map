# 坐标核验与坐标系方法

更新：2026-09-12 · v0.9

## 目标

网页底图使用高德地图，因此静态发布坐标统一使用 **GCJ-02**。项目不追求“每个编号都必须有一个点”，而追求每一个发布点都能说明它代表什么、来源在哪里、排除了哪些常见误认。

## 发布优先级

1. 文物主管部门、遗址保护机构、UNESCO 世界遗产中心等一级来源直接公布的本体/代表坐标或 GIS。
2. 高德地图中的文物本体 / 石窟本体 POI，并与官方位置描述交叉核验。
3. 正式调查报告、学术测绘提供的坐标；来源必须能够追溯。
4. 来源清楚的 WGS84 本体坐标，至少再有一条独立的官方/学术位置证据支持。
5. WGS84 点通过 `src/geo/wgs84ToGcj02.ts` 统一转换为 GCJ-02，并把原始坐标、转换方法、核验说明写入 `coordinateSource` / `verificationNote`。

## 禁止直接发布

- 县城、乡镇、行政区中心。
- 山体中心、景区入口、游客中心、停车场、公交站。
- 与遗址同名但性质不同的邻近对象，例如 **克孜尔尕哈烽燧 ≠ 克孜尔尕哈石窟**。
- 一次自动 POI 搜索的首条结果。
- 复合国保项目的人为平均中心 / 几何中心。

## WGS84 → GCJ-02

项目使用确定性的大陆地区标准转换实现：

```ts
import { wgs84ToGcj02 } from '../src/geo/wgs84ToGcj02'

const [lng, lat] = wgs84ToGcj02(sourceLng, sourceLat)
```

转换逻辑有 Node 单元测试。转换只能解决**坐标系**问题，不能解决“这个坐标究竟是不是正确遗址”的来源问题，因此必须先做人文地理消歧，再转换。

## 遗址群关系线

`src/map/getGroupRelationLines.ts` 只为 `siteExtent: group` 且至少存在两个已核验显示点的项目生成关系路径。网页将其绘成虚线，并默认关闭。

它表达的是：

> 这些点在本数据库中属于同一个父级国保 / 展墙项目。

它**不表达**：保护范围、建设控制地带、洞窟连续分布范围、古道、行政界线或历史交通路径。

## 空间范围几何与来源链（v0.8）

v0.7 已加入 `Polygon` / `MultiPolygon`，但几何发布遵守更严格的门槛：

- 法定保护范围、建设控制地带和学术研究分布范围必须分层。
- 只有文字四至时保存为 `text-only`，详情可读，但地图不绘制。
- 公开经纬上下限可以确定性转换为 GCJ-02 外接矩形，但只能标记为 `published-site-extent`，不得称作法定保护范围。
- Polygon 只接受可核验坐标、矢量或可可靠配准的正式图纸。

完整规则见 `docs/spatial-boundaries.md`；具体来源等级、面积、坐标系与推导过程见 `docs/spatial-source-ledger.md`。

## 下一步

优先寻找正式保护规划图、坐标表或公开 GIS，把更多 `text-only` 记录升级为可核验几何；同时继续保持“组内关系线 ≠ 范围边界”。


## v0.9 源资产登记

坐标 / 范围的“证据内容”和“承载证据的文件或网页”从 v0.9 起分开记录。`src/data/spatialSourceAssets.ts` 保存官方地图 PDF、地理数据页、法规和案例的处理状态；`SiteSpatialExtent` 继续保存具体空间主张。

因此：

- UNESCO 官方地图 PDF 可以是 `official-primary`，但只要尚未提取 / 配准，就只能是 `georeference-needed`；
- UNESCO geographical data 页面可用于代表坐标和面积，但不能用面积反推边界；
- 任何源资产的 `linkedExtentIds` 都必须通过测试解析到实际范围记录；
- 未来成功下载原始 PDF 后，应补 SHA-256、目标页码、控制点、配准误差等，不覆盖现有远程登记记录。

详见 `docs/spatial-asset-registry.md`。
