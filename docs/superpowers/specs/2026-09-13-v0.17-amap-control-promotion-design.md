# v0.17 高德控制点联动与人工晋升工作流设计

日期：2026-09-13

## 目标

把 v0.16 的配准草稿工作台连接到现代高德底图，并建立一个明确、可审计、不会自动污染 canonical 数据的边界晋升流程。

## 一、高德控制点联动

工作台中的源图像仍然提供 pixel 坐标；现代高德地图提供 GCJ-02 地面坐标。用户先在源图点击一个 pixel，再打开内嵌高德取点器，在现代底图点击对应真实地物。系统把高德 GCJ-02 点击点确定性反算为 WGS84，作为 georeference control 的 ground 坐标。

每个由高德生成的控制点保留：

- ground WGS84（用于配准数学）
- 原始 GCJ-02 点击坐标
- `groundSource = amap-click`
- 控制点角色 `fit` / `check`

手工修改 ground 经纬度后，原有高德来源标记自动清除，避免伪造 provenance。

## 二、浏览器取点器

工作台内嵌一个独立 AMap 面板，不要求关闭全屏配准工作台。地图中心优先使用当前遗址 verified 父级点，其次 verified 子点，最后使用全国默认中心。

点击地图只产生待确认位置；用户必须点击“使用此位置”才写入 pending control。高德 Key 缺失时显示配置提示，不阻断手工输入控制点。

## 三、Canonical extent patch

当且仅当：

1. 已选择一个 `SiteSpatialExtent`；
2. 该范围当前不是 `geometryStatus: verified`；
3. 已完成至少3个边界像素点；
4. v0.16 `assessReviewReadiness()` 返回 `strong`；
5. 配准/面积/holdout/LOO 等 QA 已生成；

工作台才能生成 `draft-unreviewed` canonical patch。

Patch 同时保存：

- WGS84 Polygon（研究/审计）
- GCJ-02 Polygon（canonical AMap geometry）
- session id / site id / extent id
- QA snapshot
- source map target id
- 生成时间

## 四、人工确认门

Patch 不能由浏览器自动写入 canonical 数据。用户必须输入精确确认令牌：

`APPROVE <site-code> <extent-id>`

确认后 patch 状态变为 `human-approved` 并下载 JSON。

## 五、Canonical registry

项目新增 `src/data/reviewedExtentPatches.json`，初始为空。运行：

`python scripts/apply_reviewed_extent_patch.py <approved-patch.json>`

脚本仅接受：

- `reviewStatus = human-approved`
- site / extent 存在
- patch schema 合法
- 默认不覆盖已有同 site+extent patch

运行后把 patch 写入 canonical registry。`sites.ts` 在导出 `sites` 时应用 registry：对应 extent 被升级为 `geometryStatus: verified`，geometry 使用 GCJ-02，derivation 标记 `georeferenced-official-map`，同时保留 patch/session provenance。

## 六、安全边界

- AMap 点击点不自动加入控制点。
- `strong` 只允许生成晋升草稿，不等于已审核。
- 浏览器不能直接改 canonical registry。
- 已 verified extent 默认禁止被新 patch 覆盖。
- patch registry 不包含图片原文件。
- 所有变更均保留 human confirmation 与 session provenance。
